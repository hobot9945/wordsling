# Контекст проекта: Wordsling

**Суть:** Система Speech-to-Text на базе Gboard.

**Текущий фокус:** Rust-серверная часть проекта — рефакторинг тестового стенда и написание интеграционных тестов для механизма подстановок и стирания.

## Текущее состояние пайплайна Wordsling server

Пайплайн полностью собран и работает end-to-end: `TcpServer -> Lexer -> FrankenLab -> ScreenWriter`.

### Состояние FrankenLab / SurgeTable

**Реализовано и работает:**
- Механизм Eager Replacement (проактивная замена) полностью реализован.
- Операции FSM и модификации досок строго разделены.
- Разделочная доска (`_cutting_board`) очищается при стабилизации (содержит только нестабильную зону).
- `_prune_if_needed()` применяется только к `_franken_board` (сохраняет левый контекст до 2000 символов).
- **Обработка забоев (`_apply_gboard_erase`) реализована:**
  - Используется алгоритм стирания блоками справа налево.
  - Корректно разруливается состояние живого кандидата (сброс в гребень при пробитии).
  - Корректно обрабатывается частичное разрушение зубцов (откат подстановки + восстановление `surviving raw tail`).

## Рекомендуемый следующий шаг

1. **Рефакторинг `lexer_plus_text_processor.rs`:**
   - Разбить монолитный тест на универсальную функцию-раннер и набор изолированных тестов.
   - Сигнатура раннера должна принимать массив входящих `chunks` и возвращать (или сразу проверять через `assert_eq!`) итоговый текст `franken_board` / сгенерированный на основе `ScreenTransfer` виртуальный экран.

2. **Написание тест-кейсов:**
   - Тест на базовый Eager Replacement (`"точка"` -> `"."`, затем `"точка с запятой"` -> `";"`).
   - Тест на стирание свободного хвоста, не затрагивающее кандидата.
   - Тест на стирание, пробивающее кандидата/зубец (проверка отката и восстановления сырого хвоста).
